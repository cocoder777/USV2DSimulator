# USV2DSimulator

基于 Unity Universal 2D 的无人艇仿真平台，支持航路点寻线和运动目标连线距离跟随。寻线验证按序到点、通过限速与终点停车；距离跟随验证自定义间距区间、相对速度和主动远离。两种任务均支持手动控制与 Jev 决策。

## 目标距离跟随

在右侧 **TASK MODE → Distance following** 选择独立跟踪地图，提供 Straight、Gentle turn、Complex、Irregular 四种目标运动场景。输入 Min / Max 后点击 **Apply distances and reset**，距离单位为米，表示两艇中心之间的直线距离；最小值必须超过两艇实体半径之和，最大值必须大于最小值。默认范围 100～200 m。任务模式与 Manual / Jev 控制方式独立。

Complex 替代原 Speed / stop：180 s 内包含 10～12°/s 快速左右转向、180° 掉头、变速、两次急停后再起步及末段停车。目标加速度 1.46 m/s²、减速度 3.5 m/s²，运动配置位于 `Assets/StreamingAssets/Following/complex.json`；原简单场景继续使用默认 1 m/s²。Complex 内配置三个障碍物，勾选／取消 **Scenario obstacles** 可对同一目标运动进行有／无障碍对比，切换会重置本轮。

Irregular 参考 Level 4 的打乱方向，使用固定种子 20261027 生成 240 s 的连续转向、折返、非等时变速和急停，保留相同目标加减速度及三个安全布局的障碍物。它是独立的目标运动脚本，不是本艇航路点任务；`python Tools/generate_following_irregular.py --check` 可核对场景是否与生成器一致，去掉 `--check` 可重新生成。

加载场景时沿目标完整运动脚本检查目标半径与障碍安全圈、整个巡航活动包络的距离，存在重叠则拒绝加载；这只约束场景生成，不向 Jev 提供目标未来路线。运行轨迹另行记录目标与障碍物的实际最小实体／安全净距。目标路线安全不代表本艇能够安全跟上，复杂场景用于验证当前策略的边界。

场景位于 `Assets/StreamingAssets/Following/`，没有航路点。目标未来运动脚本仅在 Unity 中运行，不进入报文或 Jev 请求；目标与本艇、障碍物共用暂停与物理步进。Python 根据当前目标位置、实际速度和运动方向，计算两艇连线上的间距参考位置、匀速短时预测及原 64 个候选动作的距离／相对速度／碰撞后果，由 Jev 选择动作。参考点位于目标朝向本艇的一侧，距目标为区间中点；它不随目标运动方向绕转。不要求处于目标后方。过近或预测将逼近下限时，应主动机动拉开距离，尤其不能以停车等待应对迎面目标；距离过远时仍应追近，不能仅因目标朝向本艇就逃离。显式 Stop via Jev 仍优先执行停车。不实现拦截、滤波或历史轨迹跟随。

超距且本艇航向背离目标时，先恢复航向再追近。在距离区间外半段、距离正在增大时，还会比较预计到达上限的时间与转向恢复所需时间，必要时提前转向，避免超过上限后才开始掉头。决策请求补充当前航向误差及候选转向后的角度误差，允许掉头初期短暂增距，要求保持有用的安全转向，避免沿背离方向继续加速。零速指令不转向；Jev 自行选择安全的非零转向速度，最低速度不是固定要求，仍无本地动作代选。

跟踪请求将 64 份候选中的重复规则、单位和假设合并到公共说明，每个候选使用数值表字符串并保留明确警告。运动／碰撞预测、连线参考坐标和旧纵横向诊断保留；跟踪不再计算未使用的中点和路径速度数组，寻线继续使用完整数据。Unity 扩展省略恒为零的过渡时间及跟踪不用的到达半径，快照关联保留。已有 Python 客户端需先退出再启动以加载该适配变化。

目标以紫色圆及轨迹显示，红／绿圈是最小／最大距离，青色十字是连线距离参考位置。进入距离区间不会结束任务；到达场景指定仿真时长后结束并导出双艇轨迹与统计，仍可能以非零速度结束。距离区间内时间占比、旧后方尾随诊断占比、距离越界及最小实体净距分别报告；结束不代表跟踪合格。Stop via Jev 使用独立停车目标，暂停距离保持要求；若制动途中达到场景时长，仍等待实际停车后结束并完整导出。

目标任务使用项目新增 `code="targetFollowing"`，参数为 `platCode/targetPlatformId/minFollowingDistanceM/maxFollowingDistanceM`；它不是甲方已定义的算法编码。现有 `trackingMode` 继续表示航路点寻线。线侧速度仍为节，位置为经纬度，距离为米。

## 环境与启动

- Unity **6000.6.5f1**，打开 `Assets/Scenes/Main.unity` 并进入 Play。
- Python 3.10+；Jev 客户端仅依赖标准库，轨迹绘图依赖 Matplotlib。

在项目根目录执行：

```powershell
New-Item -ItemType Directory -Force Logs | Out-Null
python jev_api/boat_client.py --log Logs/jev.jsonl
```

等待终端显示 `Jev worker listening`，在 Unity 选择地图、切换 Jev 模式，点击 **Start Jev**。8 个候选航向每隔 45°，共 64 个速度/航向组合。默认单次动作和决策采样周期为 **1.00 s 仿真时间**，可在面板调整。

## 运行规则与操作

Unity 采样后暂停，等待 Jev 从 **8 档非负航速 × 8 个全局航向**中选择一个动作；执行指定时长后再次采样。航向正北为 0°，顺时针增加。航速与转向按物理上限逐步变化：默认最大航速 **50 节**，最大加速度 **1.46 m/s²**、减速度 **1.75 m/s²**，最大角速度 **12°/s**、角加速度 **4°/s²**。转向会加速、匀速及制动，连续相同目标延续当前状态。参数可调；面板 Max forward speed 使用节，内部物理使用 m/s。

地图虚线仅供显示，不发送给 Python 或 Jev，也不约束点间走法。每点 `routeSpeed` 是通过圈内的实际航速上限（m/s），不是要求达到的参考速度。地图显示“计划航速（通过上限）”及实测通过最高航速。船长默认 11.6 m、宽 3.4 m，以外接圆（半径约 6.044 m）判断碰撞；打卡半径为包络半径乘可调倍率，默认 5 倍（约 30.22 m），中间点按序进入打卡圈，终点圈内还须低速停车；超限会记录和显示，不由执行器强制限速或阻止打卡。Unity 负责判定任务完成，并自动保存轨迹。

每张地图自动生成最多 3 个运动障碍物。小/大目标避碰安全半径默认 50/90 m，大目标可在 80～100 m 调整；实体碰撞半径另设，默认 3/12 m。红圈表示实体、橙圈表示避碰安全范围，均与本艇圆形包络计算净距。侵入安全圈记录安全距离不足，实体接触才判碰撞失败。船与障碍物共用仿真步进，等待 Jev 时共同暂停。碰撞优先于同一步的终点判定，并保存轨迹；失败后按 R 或重新加载地图开始新一轮。

地图坐标默认按原布局放大 40 倍，航点限速与采样密度由 `Tools/map_profile.json` 配置。修改后运行 `python Tools/generate_fixed_curve.py` 和 `python Tools/generate_map_levels.py` 重新生成。船体尺寸仅缩放视觉子对象，世界仍为 1 单位 = 1 米；镜头默认以船为中心、固定视野，取消航速前视与位置缓动，鼠标滚轮缩放，Map overview 手动切换全图；航速变化不会自动缩放。

| 操作 | 功能 |
| --- | --- |
| W/S、A/D | Manual 模式加速/减速、左/右转 |
| R | 重置船、任务进度与轨迹 |
| 模式按钮 | Manual / Jev |
| Start Jev | 开始决策循环 |
| Retry Jev | 请求失败后重新采样决策 |
| Level 0～4 | 切换地图并重置 |
| 右侧 Simulation speed 滑块 | 1×～10× 仿真加速，默认 1×；Reset speed to 1x 恢复正常速度 |

加速通过 Unity `Time.timeScale` 提高仿真时间推进速度，船和运动障碍物同步加速，固定物理积分步长仍为 0.02 s，不改变航速、加速度上限或动作的仿真时长。Manual 与 Jev 模式均生效，等待 Jev 决策时仍暂停，模型推理耗时不会被加速；高倍率下实际加速效果受机器性能影响。

## 轨迹导出

Editor 导出到 `Logs/trajectories/`；独立程序导出到 `Application.persistentDataPath/Trajectories/`。首次使用绘图：

```powershell
python -m pip install -r Assets/StreamingAssets/Tools/requirements.txt
python Tools/configure_trajectory_plot.py
```

## 当前范围与文档

当前采用暂停决策，支持简化运动障碍物，不模拟风浪或真实动力系统。障碍物和本艇统一发送甲方兵力融合态势（经纬度、节、运动方向），Jev 请求仍明确描述障碍物，新增其速度和方向，候选净距继续使用当前位置快照估计，长预览覆盖转向/制动所需时间，不预测障碍物未来位置。

Unity/Python 已按最新 `jev_api_guoliang/` 核对甲方 `0x0660/0x0060/0x0666/0x0662/0x0664` 大端帧、态势组播及JSON分片。任务列表只含目标，`currentRoute`为已完成数量；地图起点仍保留在Unity。`unity_only`保留采样关联、快照时戳、兼作实体清单的半径表、动作时长、速度上限、受限动力学配置、当前艏向/角速度/保持目标状态、障碍物安全半径与到达/停车阈值；删除重复身份、进度、整份候选表和暂停常量，状态回包也不重复动作。这是本项目扩展对象，不是甲方报文类型。默认Unity/Python点播端口5005/5006，态势组播`239.255.0.10:18010`，回环网卡。

`jev_api_guoliang/`是面向甲方的独立程序，本项目运行不依赖它；其最新默认后端为Kev-4B，包含部署脚本和历史实测记录，但当前副本未附权重。本项目仍用真实Jev和64 Choice。其持续控制、自动续发/重试及`routeRadius`作到达圈的行为不移植，保持Unity暂停等待、物理判定与当前避障策略。

线侧速度全部为节；地图、轨迹与内部物理仍用 m/s。Jev 默认用节表达速度、用米表达距离，说明 `1 节 = 1852/3600 m/s`；启动 Python 时加 `--jev-speed-unit mps` 可仅切回模型的 m/s 表达。既有 Python 客户端需重启加载本次协议改动。算法状态 1/2/3 分别表示执行中/完成/决策失败，碰撞仍由 Unity 单独判定。物理积分默认 0.02 s，每个 1 s 动作包含 50 步；等待模型会延长墙钟报文间隔，不是严格实时 1 Hz。任务/态势按决策采样发送，状态在处理、结果、完成和失败时反馈。转弯半径暂不处理。
