# 确定性控制基准与 Laya/Kev 对照（2026-10-18）

本轮建立了不依赖模型的确定性控制基线，在独立 Unity 副本中使用原项目的 8×7 动作空间、实际动力学、0.4 秒动作保持和 `MissionProgress` 任务判定，完成了 9 个场景的闭环运行。原项目的默认客户端、场景、动力学参数和 56 动作定义未修改。

## 2. 控制器设计

### 2.1 PD / 目标方位控制

- 由目标相对位置求方位角 `bearing = atan2(left_m, forward_m)`。
- 期望角速度 `omega_des = clamp(k_psi * bearing, ±max_yaw_rate)`。
- 角加速度加入阻尼前馈：`alpha = angular_damping * omega_des + k_omega * (omega_des - yaw_rate)`。
- 打卡点使用巡航速度，并按航向误差衰减；终点使用制动距离曲线，并在圈外保留 `creep_speed` 以进入圈内。
- 纵向加速度：`a = linear_damping * speed + k_v * (v_des - speed)`。
- 最后分别映射到 8 档线加速度和 7 档角加速度中最近的一档。

### 2.2 单步前视

- 枚举全部 56 个联合动作。
- 用与 Unity 完全相同的离散积分预测未来 20 个 0.02 秒物理步。
- 终端代价包含目标距离、航向误差、角速度、终点超速、倒车和动作切换惩罚。
- 平局按较小加速度幅值、较小角加速度幅值、较低索引确定，保证可复现。
- 该方法直接处理离散档位和 0.4 秒保持，用于判断“动作空间 + 动力学”是否具备完成任务的能力。

### 2.3 调参记录

首轮 Unity 运行发现两个控制器缺陷：

1. 单步代价过重惩罚角速度，远距离左右目标始终不转向。
2. 终点制动曲线在圈外 1.03 m 处就把目标速度降为 0，导致停在圈外。

修正为更高的航向权重、更低的角速度权重，并在终点圈外加入 0.4 m/s 的 creep 速度。修正后离线闭环与 Unity 实跑均通过全部场景。

## 5. 对动作空间与动力学的结论

- **动作空间足够**：8 档线加速度 × 7 档角加速度能够完成正前方、左右前方、倒退制动、角速度抑制、终点停车和多航点路线。
- **0.4 秒保持不是阻塞因素**：两种经典方法都在该保持机制下完成全部场景；单步前视显式预测 20 个物理步，PD 只做连续量到最近档位映射也能完成。
- **当前观测信息足够完成上述场景**：经典控制器只使用与模型输入等价的量（速度、角速度、目标相对位置、到达半径、停车阈值、动力学参数），没有使用未来航点或参考曲线前视。
- **曲线跟踪是单独问题**：仅跟踪当前航点时，PD 的路径偏差 0.88 m、单步前视 2.18 m；若要求严格贴合参考曲线，应单独增加路径前视信息并重新测试，不能把“通过必过点”当作曲线跟踪成功。

## 6. Laya/Kev 对照现状

本轮尝试了同场景 Laya 实跑，但未能完成全量对照：

- Laya 8010 在运行前可用。
- `ahead_rest` 收到 21 次真实响应，仿真推进 8.4 秒；模型持续选择负线加速度和满右转（动作索引线 2、角 0），最终速度 −1.0 m/s、目标距离 7.35 m、航向误差约 86°，未通过打卡点。
- 随后服务在运行中出现 `WinError 10061` 连接拒绝，后续场景未能获得有效决策；工具没有自行重启服务。
- 单次 Laya 决策耗时约 5～13 秒，旧墙钟预算下会先触发 wall timeout；已将 Unity 侧墙钟预算放宽，但本轮未再继续重跑。

Kev 8009 本轮未监听，未执行同场景运行。此前 `docs/模型控制诊断.md` 已记录 Laya/Kev 在基本方向、制动和 56 选项匹配上的失败，这些结果来自不同的诊断输入，不能与本次九场景完成率直接合并。

因此本轮可以确认的是：

- 经典控制器在同一 Unity 动力学和动作空间下 9/9 完成。
- Laya 在本次真实 `ahead_rest` 场景中仍选择倒退和持续转向，未完成。
- Kev 的同场景数据待服务启动后补跑。
- 全量 Laya/Kev 对照必须使用同一场景套件重跑后才能下结论。

## 7. 原因归类

| 类别 | 本轮证据 | 结论 |
| --- | --- | --- |
| 动作空间或动力学限制 | classic/lookahead 与 classic/PD 均 9/9 | 排除 |
| 输入信息不足 | 经典控制器使用等价可观测信息即可完成 | 对当前场景排除；严格曲线跟踪另议 |
| 模型数值决策能力不足 | Laya 在正前方目标持续负加速度和满右转；历史 Kev 同类失败 | 主要剩余原因 |
| 控制频率/动作保持时间 | 0.4 秒保持下两种经典方法均成功；模型推理慢只影响墙钟，不影响暂停中的仿真 | 不是控制失败原因；是测试吞吐问题 |

## 8. 下一阶段建议

1. **先补全同场景模型对照**：服务稳定后运行
   ```bash
   python Tools/control_benchmark.py --controller laya --output Logs/control-benchmark-<new>-laya
   python Tools/control_benchmark.py --controller kev --output Logs/control-benchmark-<new>-kev
   ```
   不要同时占用 Laya/Kev 显存；工具不会自行启停服务。
2. **停止以提示词穷举为主方向**：本轮 classic 基线表明任务和动作空间可实现，剩余差距主要在模型根据数值状态选择动作的能力。
3. **把经典控制器作为标签生成器，而不是默认控制覆盖**：在更大状态分布上记录 `(state → classic action)`，用于下一阶段的监督学习/蒸馏或模型适配评估；本轮不训练、不覆盖模型输出。
4. **模型输出形式可单独验证**：比较“56 选 1”与“连续 a/α 输出后离散化”两种接口，判断候选数量和数值映射对模型的影响；不继续做大规模提示词穷举。
5. **曲线跟踪单独设条件**：若任务要求贴合参考曲线，增加路径前视输入并单独测试；仅跟踪当前航点的结果不能代表曲线跟踪能力。
