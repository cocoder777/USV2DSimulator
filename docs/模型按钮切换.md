# Jev / Laya / Kev 按钮切换

在 Main 场景进入 Play 后，右侧 MODEL 提供：

| 按钮 | 行为 |
|---|---|
| Run Jev | 使用云端 Jev，恢复 GitHub `42088e5` 的运行参数，重置当前地图后运行 |
| Run Laya | 准备 Laya-multilingual 的 CUDA 服务及 compact 客户端，重置当前任务后自动运行 |
| Run Kev | 准备 Kev-0.8B 的 CUDA 服务及 original 客户端，重置当前任务后自动运行 |
| Restart same model | 保留已加载服务和客户端，保存上一轮后从当前地图初始状态重跑 |

按钮会自行切到 Jev 控制模式并开始决策。该模式是通信执行模式，实际模型以 Model 显示为准：Jev (cloud)、laya 或 kev。本地模型文件和环境仍在 D:\AI，未复制到项目。两种本地模型保留原始权重、各自输入格式、全部 56 动作和 UDP v5。默认命令行客户端依然是 Laya；按钮失败不会自动替换模型。

## 云端 Jev 与 GitHub 原始配置

本次核对的 GitHub master 为 `42088e5d891a701ff838bef45be5445977ed769f`。Run Jev、右侧 Start Jev (cloud / original)、底部 Run Jev (cloud) 都明确选用云端，不再启动上次选中的本地模型。

| 项目 | Jev 按钮使用的配置 |
|---|---|
| 接口 / 模型 | `https://api.typesafe.ai/v1/systemone` / `jev-latest` |
| 提示词 | 仓库该版本的 original 输入，保留全部 56 个联合动作；不附加 Laya 的 token 预算字段 |
| 动作时长 / 固定步长 | 0.4 s / 0.02 s |
| 最大前进 / 后退速度 | 5 / 1 m/s |
| 最大线 / 角加速度 | 1.5 m/s² / 60 deg/s² |
| 最大角速度 | 45 deg/s |
| 线 / 角响应时间常数 | 0 / 0 s |
| 线 / 角阻尼 | 0.2 / 1.2 s⁻¹ |
| 通信与等待 | 原 UDP v5，等待决策时暂停仿真；HTTP 请求无决策超时 |

点击 Jev 会恢复上表的运行时参数；不会写回场景或修改动力学公式。保留当前选中地图，其任务与初始状态仍由地图文件提供。Laya/Kev 按钮沿用当前参数；比较三个模型时应先统一上述参数。

云端按钮依次读取进程、Windows 用户及系统环境变量 `JEV_API_KEY`；没有环境变量时，读取项目根目录的 `.env.jev.json`，格式为 `{"JEV_API_KEY":"你的云端密钥"}`。该文件已由 `.gitignore` 的 `.env.*` 规则排除，不会提交密钥，也不把密钥写入命令行或日志。配置修改后再次点击按钮即可，无需重启 Unity。也可在自己的 PowerShell 中执行：

```powershell
[Environment]::SetEnvironmentVariable('JEV_API_KEY', '你的云端密钥', 'User')
```

未配置时按钮明确提示，不重置当前运行或关闭现有客户端。HTTP 鉴权或服务错误会暂停并显示错误，不会回退 Laya/Kev。云端只借用 D:\AI 下已有 Python 解释器，不启动或加载本地模型；无需 CUDA 服务。

切换时先停止当前决策并保存轨迹，再重置艇和任务、关闭旧客户端。本地模型会释放另一模型的显存，等待服务身份/GPU 检查通过后启动新客户端；首次加载可能需要几十秒。云端不启动本地模型服务。模型、仿真时间、打卡数、最近一次决策耗时和动作显示在面板，HUD 显示实际选中的模型。模型尚未就绪时不能提前执行。

Laya/Kev 切换时地图、动力学参数、参考路线和动作时长保持当前设置；Jev 则应用上表参数。每轮使用该地图已有初始位置、航向和速度。比较时让模型运行相同的仿真时间，不能只按观看的墙钟秒数比较。切换不说明模型已能正确导航。

R 和地图切换沿用原有重置行为，不自动开始下一轮；用 Start selected / external client 继续已选模型，或 Restart same model 从头重跑。点 Start Jev 会重新选择云端 Jev。加载期间如果使用 R、换模式或改任务，自动起航会取消，服务准备好后需手动开始。手动 WASD 模式保留。

## 日志与轨迹

- 每次按钮选型使用独立 `Logs/model-switch/<时间_唯一编号>/`，包括 worker.jsonl 的完整观测/payload/原始回答、耗时、服务启停日志以及管理状态。
- 切换模型、Restart same model、停止 Play 会保存尚未完成的当前模型轨迹；任务完成仍自动保存。数据和 PNG 位于 `Logs/trajectories/`。
- 轨迹 JSON 增加 controller 和 worker_log；图片标题显示模型。未完成的 result 为 model_switched、run_restarted 或 play_stopped，不能按 completed 统计。
- 绘图复用原有 Python/Matplotlib 配置。绘图失败时 JSON 仍保留，可在面板重试；缺少绘图环境不会阻止模型控制。
- 本轮保存的图片显示一轮模型轨迹及参考路径；切换后可打开上一轮图片对照查看。没有新增自动多模型叠加图或在线训练。

## 进程与异常处理

只管理按钮创建的客户端。若端口已有客户端，可读取端口进程，核对绝对脚本路径为本项目 boat_client.py、相同 Unity/客户端端口和进程启动时间后接管；无法确认归属时保留进程并提示关闭旧客户端。相对路径启动的旧程序可能需要手动关闭一次。不会按 python.exe 名称批量终止进程。

模型服务复用 D:\AI 下原有启停脚本，脚本会验证服务进程身份。错误权重路径、CPU 服务、错误 revision、未知端口占用均明确失败。切换失败时当前轮保持暂停，不把旧模型动作带进新轮。

停止 Play 时通知管理程序退出，清理它的 Python 客户端及本次由它启动且身份未被替换的服务；直接复用的已有服务可以保留。正在加载时需等加载返回后再清理，界面线程不会被阻塞。Editor 意外退出时通过父进程句柄检查触发清理。同一项目的多个按钮会话串行使用部署，避免不同 Editor 同时抢占 GPU。原始手工启动方式仍兼容。

LocalModelSwitcher 在 BoatParameterPanel 初始化时自动挂载，不需要改场景 Inspector。默认 deploymentRoot 为 D:/AI。修改部署位置时可在组件配置；Windows 构建包还需设置 projectRoot 指向包含 Tools 和 jev_api 的项目目录，当前不会把 Python、权重或脚本打进构建包。
